# 项目知识总结

本文档汇总“班主任工作台”从开发到上线过程中使用到的所有知识，包括部署平台、Supabase、前端代码知识点和踩坑记录，便于后续维护与复用。

## 一、部署平台知识

### 1. GitHub Pages

- 原理：GitHub 托管仓库静态文件，默认域名 `用户名.github.io/仓库名`。
- 自动部署：仓库 `.github/workflows/deploy-pages.yml`，推送到 `main` 时执行 `npm ci && npm run build`，再用 `actions/configure-pages`、`upload-pages-artifact`、`deploy-pages` 发布 `dist`。
- 路径问题：子路径部署必须设置 Vite 的 `base`，本项目通过环境变量 `GH_PAGES=true` 把 `base` 设为 `/teacher-dashboard-cn/`。
- SPA 路由：GitHub Pages 不支持服务端回退，未命中路径会返回 404。本项目用 `public/404.html` 保存原始路径到 `sessionStorage`，跳回首页后由 `App.tsx` 恢复路由。
- 深链接首次访问会经历 404 跳转，服务工作者（PWA）激活后导航由缓存接管。
- Actions 密钥：Supabase 地址与匿名密钥放在仓库 Secrets 中，构建时注入环境变量。

### 2. Cloudflare Pages

- 两种方式：Git 集成自动构建，或 Direct Upload 直接上传 `dist`。
- 本项目使用 Direct Upload API + 自写脚本 `scripts/cf-pages-upload.mjs`。
- 核心流程（Wrangler 内部实现）：
  1. `GET /accounts/{accountId}/pages/projects/{project}/upload-token` 获取上传 JWT。
  2. `POST /pages/assets/check-missing` 检查哪些哈希未上传。
  3. `POST /pages/assets/upload` 用 JSON base64 上传文件（key=哈希，value=base64，metadata.contentType）。
  4. `POST /pages/assets/upsert-hashes` 登记哈希。
  5. `POST /accounts/{accountId}/pages/projects/{project}/deployments` 提交 multipart 表单：`manifest`、`branch`、`_redirects`。
- 文件哈希不是 SHA-256，而是 `BLAKE3(base64(文件内容) + 扩展名).hex` 取前 32 位；哈希错误会导致部署成功但访问 404/500。
- manifest 的 key 需要带前导斜杠，如 `/index.html`。
- `404.html` 会优先于 `_redirects` 的 `/* /index.html 200` 规则，导致 SPA 路由失效；因此 Cloudflare 部署时跳过 `404.html`。
- 本机 `wrangler` 的 Node fetch 连不上 Cloudflare API，改用 `curl.exe` 调 REST；OAuth token 过期后通过 `dash.cloudflare.com/oauth2/token` 的 `refresh_token` 刷新。
- 部署脚本需设置 `WRANGLER_SEND_METRICS=false` 时仍可能失败，直接用 `wrangler.cmd` 或 REST 更稳。

### 3. Netlify

- 自动部署：连接 GitHub 仓库，推送到分支后自动构建。
- 配置文件 `netlify.toml`，曾因文件开头残留 `<<<<<<< HEAD` 合并冲突标记导致 TOML 解析失败。
- SPA 回退：`public/_redirects` 中 `/* /index.html 200`。
- 常用命令：`netlify deploy --prod`，Token 为 `nfp_` 开头。
- 本项目最终改用 GitHub Pages + Cloudflare，Netlify 站点保留可访问。

### 4. Vercel

- 支持 Git 自动部署，配置文件 `vercel.json`。
- 本机曾因无法登录 Vercel 而改用其他平台。
- 国内访问不稳定，因此未作为正式部署渠道。

### 5. 腾讯云 EdgeOne

- 曾通过 EdgeOne 部署，域名形如 `teacher-dashboard-cn-xxxx.edgeone.cool`。
- 国内访问通常更快，但需要备案域名、实名认证等流程。
- 本项目最终未采用。

### 6. Gitee Pages

- 国内平台，曾尝试把构建产物推到 `gitee-pages` 分支镜像同步。
- 部分账号没有 Gitee Pages 入口，且免费版审核/更新限制较多，未作为正式渠道。

## 二、Supabase 知识

### 1. 数据模型

表结构：

- `students`：身份证号 `id_card` 为主键，含姓名、班级、选科、父母信息、备注。
- `exams`：考试，含名称与日期。
- `exam_scores`：成绩，复合主键 `(student_id, exam_id, subject)`，含原始分 `raw_score`、赋分 `assigned_score`、校名次 `school_rank`、班名次 `class_rank`。
- `class_teachers`：班主任账号，班级号为主键，含姓名与密码。
- `schedule_events`、`reminders`：日程与提醒，含 `owner` 字段区分管理员共享/班主任私有。
- `user_settings`：预留设置。

### 2. PostgREST REST API

- 基础地址：`https://项目ref.supabase.co/rest/v1/表名`。
- 匿名公钥 `sb_publishable_...` 用于前端。
- 服务密钥 `sb_secret_...` 用于脚本/管理。
- 常见操作：`select`、`order`、`eq`、`in`、`is.null`、`upsert`、`delete`、`Range` 分页、`Prefer: count=exact`。
- 默认单次最多返回 1000 行，大数据量必须分页（`Range: 0-999`、`1000-1999`…），本项目用并行分页加载 4027 名学生和 28189 条成绩。
- 复合主键 upsert 需要指定 `on_conflict=student_id,exam_id,subject`。

### 3. 管理接口执行 SQL

- PostgREST 只能读写数据，不能建表/改表。
- 使用 Supabase 管理 Access Token（`sbp_...`）调用：
  `POST https://api.supabase.com/v1/projects/{ref}/database/query`，请求体 `{"query":"SQL"}`。
- 用该接口执行建表、加列、更新数据等 DDL/DML。

### 4. 行级安全（RLS）

- 每张表 `enable row level security`，当前策略对 `anon`/`authenticated` 全开放，适合内网/小范围工具，但正式对外使用建议接入 Supabase Auth 并收紧策略。

## 三、前端代码知识点

### 1. React + TypeScript + Vite

- Vite 负责开发服务器与生产构建；`tsc -b` 先做类型检查再构建。
- 路径别名 `@/` 指向 `src/`。
- 环境变量以 `VITE_` 开头，构建时注入。

### 2. 状态管理（Zustand）

- `useStore` 统一管理学生、成绩、考试、班级、日程、提醒等数据。
- `useAuth` 管理登录会话，持久化到 `localStorage`。
- 跨 store 调用：`useAuthStore.getState().session`。
- 防重复加载：用模块级 `loadPromise` 缓存加载 Promise。

### 3. 路由与登录守卫

- `BrowserRouter basename` 区分 GitHub Pages 子路径与其他平台根路径。
- `RequireAuth` 组件：未登录跳转 `/login`。
- 路由 `PageRouter` 同步侧边栏激活状态。

### 4. 登录与权限

- 管理员：`admin/111`，可切换全部班级、修改所有成绩。
- 班主任：班级号 + 密码，从 `class_teachers` 校验，只能看本班。
- 权限控制：管理员才能看到“编辑成绩”入口；班主任可以管理学生、家长信息、备注和自己的账号密码。

### 5. 成绩计算

- 总分 = 语数英原始分 + 选考三科赋分，存到总分行的 `raw_score`。
- 班内排名用“标准竞赛排名”（同分同名次），按班级分组计算。
- 选考科目按赋分排名，语数英按原始分排名。
- 修改成绩后自动重算总分行和班内排名（`recomputeTotalRows`、`recomputeClassRanks`）。
- 性能优化：把成绩按学生建索引（`Map<studentId, Score[]>`），避免在 2.8 万条记录里反复 `find`，显著提升“全部学生”视图速度。

### 6. Excel 解析（SheetJS / xlsx）

- `XLSX.read` 支持浏览器 ArrayBuffer；`sheet_to_json(ws, { header: 1 })` 读取行数组。
- 老版 `.xls` 是 OLE2 格式，SheetJS 可解析。
- 按固定列号读取身份证、班级、选科标记、各科原始分/赋分/校名次。
- 文件名去掉扩展名作为考试名；导入前先预览学生数和成绩条数，确认后再写库。

### 7. 图表（Recharts）

- `BarChart` 画班级平均分历史。
- `LineChart` 画个人/班级总分趋势。
- `RadarChart` 画学生六科雷达图。
- `ResponsiveContainer` 自适应宽度。

### 8. PWA

- `vite-plugin-pwa` 生成 Service Worker，预缓存静态资源。
- `navigateFallback: '/index.html'` 支持离线 SPA 导航。
- 服务工作者首次激活有延迟，深链接首次访问仍会走平台 404 逻辑。

### 9. UI

- Tailwind CSS 原子类，主色 `#1e3a5f`（深蓝）与 `#2dd4bf`（青绿）。
- lucide-react 图标。
- 移动端使用横向滚动表格与卡片列表。

## 四、Windows 环境踩坑记录

- PowerShell 执行策略拦截 `npm.ps1`/`wrangler.ps1`，改用 `npm.cmd`、`wrangler.cmd`。
- PowerShell 向 Node 传中文（here-string）会变成 `??`，中文路径用环境变量传递，中文脚本写成 UTF-8 文件。
- PowerShell `ConvertTo-Json` 对字符串会包一层 `{value:...}`，构造 API 请求体时用 Node 生成 JSON 文件再交给 curl。
- 递归删除被安全策略拦截，临时目录保留并加入 `.gitignore`。
- Cloudflare OAuth token 约 1 小时过期，用 `refresh_token` 刷新后写回 `default.toml`。

## 五、常用脚本

- `scripts/import-final-exam.mjs`：把期末成绩 Excel 转成导入 JSON 并计算班内排名。
- `scripts/verify-import.mjs`：校验学生数、成绩数、总分与分科合计是否一致。
- `scripts/upload-import.mjs`：把 JSON 批量写入 Supabase（分页 POST）。
- `scripts/cf-pages-upload.mjs`：Cloudflare Pages 直传部署。
- `scripts/smoke-test.mjs`：Playwright 公网冒烟测试（登录、学生、成绩分析、Excel 导入预览、权限）。

## 六、注意事项

- 请勿把 `sb_secret_...`、`sbp_...`、Netlify Token、OAuth token 提交到仓库。
- 当前 RLS 对匿名用户全开放，对外公网使用前应接入登录鉴权并收紧权限。
- 重要数据定期用“导出 Excel”备份。
