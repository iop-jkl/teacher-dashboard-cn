# 项目知识总结（初学者教程版）

本文档写给第一次接触这个项目的初学者，从“项目是什么”开始，逐步讲到代码怎么读、怎么改、怎么推送到 GitHub、怎么部署上线。建议按顺序阅读，遇到不熟悉的词先看每一章的“小知识”部分。

## 第 1 章 这个项目是什么

“班主任工作台”是一个网页应用，帮助学校班主任和管理员管理：

- 学生信息（姓名、身份证号、班级、选科、家长电话/微信、备注）
- 考试成绩（语数英原始分、选考三科原始分和赋分、班排名、校排名、总分）
- 考试和排名分析（班级平均分历史、各科平均分、学生全科成绩排名）
- 日程安排和提醒（管理员发布的全体可见，班主任发布的只自己可见）
- 账号权限（管理员看全部班级；班主任只看自己班，不能改成绩）

它不是一个单机软件，而是“网页 + 云端数据库”的架构：

```text
浏览器网页（前端）
      │ 通过 Supabase 的 REST API 读写数据
      ▼
Supabase（云端数据库，PostgreSQL）
      ▲
      │ 部署
GitHub Pages / Cloudflare Pages（静态网页托管）
```

前端负责“页面长什么样、点击后做什么”，数据库负责“数据存在哪里、怎么查”。

## 第 2 章 技术栈是什么

项目用到的技术，每一项一句话解释：

| 技术 | 作用 |
| --- | --- |
| React | 用组件拼出页面，页面会随数据变化自动更新 |
| TypeScript | 给 JavaScript 加类型，写代码时能提前发现错误 |
| Vite | 开发服务器和打包工具，把代码变成浏览器能跑的网页 |
| Tailwind CSS | 用 CSS 类快速写样式 |
| Zustand | 全局状态管理，多个页面共享同一份数据 |
| React Router | 管理页面路由（网址和页面的对应关系） |
| Recharts | 画柱状图、折线图、雷达图 |
| Supabase | 云数据库，提供 REST API |
| SheetJS (xlsx) | 在浏览器里读取 Excel 文件 |
| vite-plugin-pwa | 生成 Service Worker，让网页支持离线缓存 |
| Git / GitHub | 版本管理和代码托管，也是部署的触发器 |
| GitHub Actions | GitHub 的自动化流程，push 后自动构建并发布 |

小知识：

- “前端”指浏览器里运行的部分，本项目在 `src/` 目录。
- “构建（build）”指把 TypeScript、JSX、CSS 编译压缩成少量静态文件，输出到 `dist/`。
- “部署”指把构建好的 `dist/` 文件放到能通过网址访问的服务器上。

## 第 3 章 项目架构

### 3.1 目录结构

```text
teacher-dashboard-cn/
├─ .github/workflows/     GitHub Actions 自动部署配置
├─ public/                静态文件（404.html、图标、_redirects）
├─ src/
│  ├─ main.tsx            程序入口
│  ├─ App.tsx             路由和登录守卫
│  ├─ pages/              页面（工作台、学生管理、成绩分析等）
│  ├─ components/         可复用组件（弹窗、表格、图表等）
│  ├─ store/              Zustand 全局状态（useStore、useAuth）
│  ├─ lib/                工具库（supabase 客户端、成绩计算）
│  ├─ utils/              工具函数（Excel 解析）
│  ├─ data/               示例/兜底数据
│  └─ types/              全局类型定义
├─ supabase/              数据库 SQL 脚本
├─ scripts/               部署、导入、测试脚本
├─ dist/                  构建输出（自动生成，不手动改）
├─ index.html
├─ vite.config.ts         Vite 配置
├─ package.json           依赖和命令
└─ .gitignore             不提交的文件
```

### 3.2 数据流

```text
用户点击按钮
   → 页面调用 useStore 里的方法
   → useStore 调用 supabase 客户端
   → Supabase 返回数据
   → useStore 更新全局状态
   → React 发现状态变化，自动重新渲染页面
```

核心思想：**页面不直接操作数据库，而是通过全局 store 中转**。这样多个页面数据一致，写数据库的逻辑也集中在一个文件。

## 第 4 章 本地环境准备

需要安装：

1. Node.js（建议 18 或更高版本）
2. Git
3. 编辑器（推荐 VS Code）


```bash

```

小知识：

- 如果没有 Supabase 环境变量，页面会显示“云端数据加载失败”，属于正常现象，见第 8 章。

## 第 5 章 代码怎么读、怎么写

### 5.1 程序入口：main.tsx

```tsx
// src/main.tsx
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import App from './App'
import './index.css'
import { registerSW } from 'virtual:pwa-register'

registerSW({ immediate: true })

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <App />
  </StrictMode>,
)
```

讲解：

- `createRoot(...).render(<App />)` 把 App 组件挂到 `index.html` 的 `<div id="root">`。
- `StrictMode` 让 React 在开发模式做额外检查。
- `registerSW` 注册 Service Worker，实现 PWA 离线缓存。

### 5.2 路由与登录守卫：App.tsx

```tsx
<Routes>
  <Route path="/login" element={<LoginPage />} />
  <Route path="/" element={<RequireAuth><Dashboard /></RequireAuth>} />
  <Route path="/students" element={<RequireAuth><StudentsPage /></RequireAuth>} />
  <Route path="/analytics" element={<RequireAuth><AnalyticsPage /></RequireAuth>} />
  ...
</Routes>
```

`RequireAuth` 是一个“守卫组件”：

```tsx
function RequireAuth({ children }) {
  const isAuthenticated = useAuthStore((s) => s.isAuthenticated);
  if (!isAuthenticated) {
    return <Navigate to="/login" replace />;
  }
  return <>{children}</>;
}
```

没登录访问任何页面都会被带到登录页。

### 5.3 全局状态：Zustand

以 `useStore` 为例，它像一个“中央仓库”：

```ts
export const useStore = create<Store>((set, get) => ({
  students: [],
  scores: [],
  loadFromSupabase: async () => { ... },
  addStudent: (s) => { ... },
  updateExamScores: (studentId, examId, updates) => { ... },
}));
```

页面里这样使用：

```tsx
const students = useStore((s) => s.students);
const addStudent = useStore((s) => s.addStudent);
```

小知识：

- `set` 用来修改状态，`get` 用来读取当前状态。
- 所有页面订阅同一个 store，任何页面修改数据，其他页面自动同步。

### 5.4 登录：useAuth

```ts
login: async (username, password) => {
  const name = username.trim();
  if (name === 'admin' && password === '111') {
    // 管理员
  } else if (/^\d+$/.test(name)) {
    // 班主任：账号是班级号，去 class_teachers 表校验密码
  }
}
```

登录成功后会：

```ts
persist(session);            // 存 localStorage
set({ session, isAuthenticated: true });
```

所以刷新页面后仍保持登录。

### 5.5 读取数据库：supabase 客户端

```ts
// src/lib/supabase.ts
export const supabase = createClient(supabaseUrl, supabaseAnonKey);
```

查询示例：

```ts
const { data, error } = await supabase
  .from('students')
  .select('*')
  .eq('class_no', 1);
```

写入示例：

```ts
const { error } = await supabase
  .from('exam_scores')
  .upsert(rows, { onConflict: 'student_id,exam_id,subject' });
```

`upsert` 表示“存在就更新，不存在就插入”，复合主键 `onConflict` 告诉数据库按哪些字段判断是否已存在。

### 5.6 成绩计算：scoreUtils

成绩表里“总分”这一行存在 `raw_score` 字段，口径是：

```text
总分 = 语数英原始分 + 选考三科赋分
```

取分规则：

```ts
export function scoreValue(s: Score | undefined): number | null {
  if (!s) return null;
  if (s.assignedScore !== null && s.assignedScore !== undefined) {
    return s.assignedScore; // 选考科目优先用赋分
  }
  return s.rawScore;        // 语数英和总分用原始分
}
```

排名规则（标准竞赛排名，同分同名次）：

```ts
// 示例：分数 [95, 90, 90, 80] → 名次 [1, 2, 2, 4]
```

修改成绩后系统会自动重算总分和班排名：

```ts
next = recomputeTotalRows(state.students, next, examId);
next = recomputeClassRanks(state.students, next, examId);
```

### 5.7 Excel 导入

“快捷操作 → 录入成绩”的流程：

1. 填写考试时间。
2. 选择 Excel，文件名自动变成考试名。
3. 用 SheetJS 解析：

```ts
const wb = XLSX.read(buffer, { type: 'array', cellDates: true });
const rows = XLSX.utils.sheet_to_json(wb.Sheets[wb.SheetNames[0]], { header: 1 });
```

4. 按固定列号读取身份证、班级、姓名、各科原始分/赋分/校名次。
5. 计算班内排名，预览确认后写入 Supabase。

### 5.8 权限控制

管理员才能编辑成绩：

```tsx
const isAdmin = session?.role === 'admin';
{isAdmin && <button>编辑成绩</button>}
```

班主任固定本班：

```tsx
useEffect(() => {
  if (!isAdmin && session?.classNo) {
    setActiveClass(session.classNo);
  }
}, [isAdmin, session?.classNo, setActiveClass]);
```

管理员默认“全部班级”，可切换：

```tsx
const classStudents = activeClass === 0
  ? students
  : students.filter((s) => s.classNo === activeClass);
```

## 第 6 章 Git 基础与推送流程

### 6.1 三个常用命令

```bash
git status        # 查看哪些文件被修改
git add .         # 把所有修改加入暂存区
git commit -m "说明文字"  # 提交一个版本
git push origin main      # 推送到 GitHub 的 main 分支
```

完整流程：

```bash
git status
git add .
git commit -m "feat: 添加新功能"
git push origin main
```

小知识：

- `git add` 只是“准备提交”，还没保存到历史。
- `git commit` 在本地保存一个版本。
- `git push` 才把本地提交上传到 GitHub。
- 提交信息建议写清楚，例如 `fix: 修复总分计算`。

### 6.2 为什么 push 就能部署

仓库里 `.github/workflows/deploy-pages.yml` 定义了自动化：

```yaml
on:
  push:
    branches: [main]
```

含义：只要 `main` 分支有新的 push，GitHub 就自动运行：

```text
1. 拉取最新代码
2. npm ci 安装依赖
3. npm run build 构建
4. 把 dist/ 发布到 GitHub Pages
```

所以“改代码 → git push” 就等于“自动部署到 GitHub Pages”。

## 第 7 章 部署流程详解

### 7.1 先本地构建验证

```bash
npm run build
```

成功后会生成 `dist/`。如果 TypeScript 有类型错误，构建会失败并提示具体文件行号，先修好再推送。

### 7.2 部署到 GitHub Pages

前置条件（只需配置一次）：

1. 仓库 Settings → Secrets and variables → Actions。
2. 添加两个 Secret：
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
3. 仓库 Settings → Pages，Source 选择 “GitHub Actions”。

之后每次 `git push origin main` 自动发布：

```text
https://用户名.github.io/teacher-dashboard-cn/
```

### 7.3 部署到 Cloudflare Pages

本项目用 Direct Upload 脚本手动部署：

```bash
npm run build
node scripts/cf-pages-upload.mjs teacher-dashboard-cn dist
```

脚本内部做的事：

```text
1. 计算每个文件的 BLAKE3 哈希
2. 获取 upload token
3. 上传缺失文件
4. 提交 manifest 创建部署
```

部署地址：

```text
https://teacher-dashboard-cn.pages.dev/
```

需要本机有 Cloudflare 登录凭证（`wrangler login` 或 `default.toml` 里的 OAuth token）。

### 7.4 其他平台

- Netlify：连接 GitHub 仓库后 push 自动部署，SPA 用 `_redirects` 文件。
- Vercel：连接仓库后自动部署，本机登录不便故未采用。
- 腾讯云 EdgeOne、Gitee Pages：国内平台，本项目仅作尝试。

## 第 8 章 Supabase 使用入门

### 8.1 获取项目地址和密钥

在 Supabase 控制台 → Project Settings → API：

- Project URL：`https://你的项目ref.supabase.co`
- anon public key：前端用的匿名公钥

本地开发时复制 `.env.example` 为 `.env.local` 并填入：

```env
VITE_SUPABASE_URL=https://你的项目.supabase.co
VITE_SUPABASE_ANON_KEY=你的匿名公钥
```

### 8.2 建表

在 Supabase SQL Editor 执行 `supabase/migrations/0003_final_exam_2026.sql`，创建：

- `students`：学生，身份证主键
- `exams`：考试
- `exam_scores`：成绩，复合主键
- `class_teachers`：班主任账号

### 8.3 行级安全（RLS）

```sql
alter table public.students enable row level security;
create policy "allow all on students" on public.students
  for all to anon, authenticated using (true) with check (true);
```

当前策略是“所有人可读写”，适合内部工具；正式对外使用建议接入 Supabase Auth 收紧。

### 8.4 常用数据操作

```ts
// 查询
await supabase.from('students').select('*');

// 带条件查询
await supabase.from('exam_scores').select('*').eq('exam_id', 'exam-2026-final');

// 插入/更新
await supabase.from('exams').upsert([{ id: 'x', name: '月考', date: '2026-08-01' }]);

// 删除
await supabase.from('students').delete().eq('id_card', 'xxx');
```

### 8.5 大数据量分页

Supabase 单次最多返回 1000 行，本项目用 `fetchAllRows` 并行分页：

```ts
const pages = await Promise.all(
  Array.from({ length: pageCount }, (_, i) =>
    supabase.from(table).select('*').range(i * 1000, i * 1000 + 999)
  )
);
```

## 第 9 章 常见问题

| 现象 | 原因和解决办法 |
| --- | --- |
| 页面显示“云端数据加载失败” | 没有配置 `.env.local`，或 Secret 没填 |
| 班级人员少 | 早期只加载前 1000 行；现在已并行分页修复 |
| 构建报类型错误 | 运行 `npm run build` 看具体文件和行号，修复后再推送 |
| GitHub Pages 404 | 深链接首次访问会走 404 跳转，属正常；PWA 激活后正常 |
| Cloudflare 部署后 500/404 | 文件哈希算法错误或存在 404.html；用本项目脚本部署 |
| PowerShell 执行 npm 报错 | 用 `npm.cmd` |
| 中文路径/中文脚本乱码 | 路径用环境变量传，脚本保存为 UTF-8 |

## 第 10 章 学习建议

如果想深入学习，按这个顺序：

1. 先读懂 `App.tsx` 的路由，知道每个页面在哪。
2. 再读 `useStore.ts`，理解数据从哪来、怎么改。
3. 然后读 `scoreUtils.ts`，理解成绩计算和排名。
4. 接着读一个页面（如 `StudentsPage.tsx`），理解页面如何调用 store。
5. 最后看 `scripts/` 和 `.github/workflows/`，理解构建和部署。

推荐学习资源关键词：

- React 官方文档（学习组件、Hooks）
- TypeScript 官方文档（学习类型）
- Supabase 官方文档（学习数据库和 REST API）
- GitHub Actions 官方文档（学习自动化部署）
- Vite 官方文档（学习构建）
