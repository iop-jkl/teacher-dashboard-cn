## 二、部署平台知识

### 1. GitHub Pages

#### 原理

GitHub Pages 托管仓库的静态文件。项目子路径部署时，URL 是 `https://用户名.github.io/仓库名/`，所以 Vite 的 `base` 必须匹配：

```ts
// vite.config.ts
const isGhPages = process.env.GH_PAGES === 'true';
export default defineConfig({
  base: isGhPages ? `/teacher-dashboard-cn/` : '/',
});
```

#### 自动部署 Workflow

```yaml
# .github/workflows/deploy-pages.yml
on:
  push:
    branches: [main]
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  build:
    env:
      VITE_SUPABASE_URL: ${{ secrets.VITE_SUPABASE_URL }}
      VITE_SUPABASE_ANON_KEY: ${{ secrets.VITE_SUPABASE_ANON_KEY }}
      GH_PAGES: 'true'
    steps:
      - uses: actions/checkout@v4
      - run: npm ci
      - run: npm run build
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist
  deploy:
    needs: build
    environment:
      name: github-pages
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

讲解：

- `on.push.branches: [main]`：推送到 main 自动触发。
- `permissions`：`pages: write` 和 `id-token: write` 是发布 GitHub Pages 必需的最小权限。
- 环境变量在 CI 中从仓库 Secrets 注入，`GH_PAGES=true` 控制 Vite base。
- 两个 job：`build` 构建并上传 artifact，`deploy` 等待构建完成后再发布，避免“发布到旧文件”。

#### SPA 路由与 404.html

GitHub Pages 对未命中的路径直接返回 404，不会回退到 `index.html`。解决方法是 `public/404.html` 先保存路径再跳回首页：

```html
<!-- public/404.html -->
<script>
  sessionStorage.setItem(
    'gh-pages-redirect',
    location.pathname + location.search + location.hash
  );
  location.replace('/teacher-dashboard-cn/');
</script>
```

前端在首页恢复路径：

```tsx
// src/App.tsx
useEffect(() => {
  const pendingRedirect = sessionStorage.getItem('gh-pages-redirect');
  if (pendingRedirect) {
    sessionStorage.removeItem('gh-pages-redirect');
    window.location.replace(pendingRedirect);
  }
}, []);
```

注意：深链接首次访问会经历 404 → 跳首页 → 恢复路径的流程；PWA 的 Service Worker 激活后，同源导航会被缓存接管，体验会变顺。

### 2. Cloudflare Pages

#### 部署方式选择

Cloudflare Pages 支持两种方式：

- Git 集成：连接 GitHub 后 push 自动构建。
- Direct Upload：手动上传 `dist`，本项目使用这种方式，并保留脚本 `scripts/cf-pages-upload.mjs`。

#### Direct Upload 核心流程

从 wrangler 源码逆向得到完整流程：

1. 获取上传令牌：`GET /accounts/{accountId}/pages/projects/{project}/upload-token`
2. 检查缺失：`POST /pages/assets/check-missing`
3. 上传文件：`POST /pages/assets/upload`（JSON base64）
4. 登记哈希：`POST /pages/assets/upsert-hashes`
5. 创建部署：`POST /accounts/{accountId}/pages/projects/{project}/deployments`（multipart）

#### 最关键的坑：文件哈希算法

Cloudflare Pages 的资源哈希不是 SHA-256，而是：

```text
BLAKE3( base64(文件内容) + 文件扩展名 ).hex，取前 32 位
```

脚本中的实现：

```js
// scripts/cf-pages-upload.mjs
function fileHash(filePath) {
  const contents = readFileSync(filePath);
  const base64Contents = contents.toString('base64');
  const extension = extname(filePath).substring(1);
  return blake3.hash(base64Contents + extension).toString('hex').slice(0, 32);
}
```

如果哈希算错，Cloudflare 会返回“部署成功”，但访问时 404/500。

#### manifest 与上传格式

```js
const manifest = Object.fromEntries(
  records.map((r) => [`/${r.rel}`, r.hash]), // 路径必须带前导 /
);
const payload = records.map((r) => ({
  key: r.hash,
  value: readFileSync(r.path).toString('base64'),
  metadata: { contentType: r.contentType },
  base64: true,
}));
```

创建部署时用 multipart 表单提交：

```text
manifest=<JSON>  branch=main  _redirects=<文件内容>
```

#### 404.html 会覆盖 _redirects

Cloudflare Pages 中只要存在 `404.html`，SPA 回退规则 `/* /index.html 200` 就会失效，未知路径会直接返回 404 页面。所以 Cloudflare 部署脚本会把 `404.html` 排除：

```js
const rootOnly = new Set([
  '_worker.js', '_redirects', '_headers', '_routes.json',
  '404.html', 'functions', '.wrangler',
]);
```

#### wrangler 的 OAuth Token 刷新

本机 `wrangler` 的 Node fetch 无法连接 Cloudflare API，改用 `curl.exe`；OAuth token 约 1 小时过期，用 refresh token 刷新：

```powershell
curl.exe -X POST "https://dash.cloudflare.com/oauth2/token" `
  -H "Content-Type: application/x-www-form-urlencoded" `
  --data-urlencode "grant_type=refresh_token" `
  --data-urlencode "refresh_token=$rt" `
  --data-urlencode "client_id=54d11594-84e4-41aa-b438-e81b8fa78ee7"
```

刷新后写回 `C:\Users\lenovo\AppData\Roaming\xdg.config\.wrangler\config\default.toml`。

## 三、Supabase 知识

### 1. 数据表设计

```sql
-- 学生：身份证号作为主键
create table public.students (
  id_card text primary key,
  name text not null,
  class_no integer not null,
  selected_subjects text[] not null default '{}',
  father_name text default '',
  father_phone text default '',
  father_wechat text default '',
  mother_name text default '',
  mother_phone text default '',
  mother_wechat text default '',
  remark text default ''
);

-- 成绩：复合主键，一个学生一场考试一个科目一行
create table public.exam_scores (
  student_id text not null references public.students(id_card) on delete cascade,
  exam_id text not null references public.exams(id) on delete cascade,
  subject text not null,
  raw_score numeric,
  assigned_score numeric,
  school_rank integer default 0,
  class_rank integer default 0,
  primary key (student_id, exam_id, subject)
);
```

设计要点：

- 身份证号唯一，替代原学号。
- 语数英 `assigned_score` 为空，选考科目两者都有。
- 总分存在总分行的 `raw_score`，`assigned_score` 为空，口径为“语数英原始分 + 选科赋分”。
- 复合主键保证“同一学生同一考试同一科目”只有一行，方便 upsert。

### 3. 1000 行分页限制（重点坑）

Supabase REST 单次请求默认最多返回 1000 行。本项目学生 4027 人、成绩 28189 条，如果只 `select('*')` 会丢失大量数据，表现就是“很多班级人员缺少”。

解决方案是分页拉取，并且并行请求：

```ts
async function fetchAllRows(table, orderBy) {
  const pageSize = 1000;
  // 先用 head 请求拿总数
  let countQuery = supabase.from(table).select('*', { count: 'exact', head: true });
  for (const o of orderBy) countQuery = countQuery.order(o.column, { ascending: o.ascending });
  const { count } = await countQuery.range(0, 0);
  const pageCount = Math.ceil((count ?? 0) / pageSize);

  // 并行拉取每一页
  const pages = await Promise.all(
    Array.from({ length: pageCount }, (_, i) => {
      let query = supabase.from(table).select('*');
      for (const o of orderBy) query = query.order(o.column, { ascending: o.ascending });
      return query.range(i * pageSize, i * pageSize + pageSize - 1);
    }),
  );
  return pages.flatMap((p) => p.data ?? []);
}
```

讲解：

- `count: 'exact', head: true` 只返回总数不返回数据，用来计算页数。
- `Range: 0-999`、`1000-1999` 等按 1000 分页。
- 必须先 `order` 再 `range`，否则分页结果不稳定。
- `Promise.all` 并行拉取，避免串行 30 次请求导致首屏很慢。

### 4. 管理接口执行 SQL

PostgREST 只能做数据读写，不能建表/加列。建表迁移使用管理 Access Token：

```text
POST https://api.supabase.com/v1/projects/{ref}/database/query
Authorization: Bearer sbp_...
Content-Type: application/json
Body: { "query": "create table ..." }
```

示例（给日程/提醒加 owner 字段并迁移旧数据）：

```sql

update public.schedule_events set owner = 'admin' where owner = '' or owner is null;

```

## 四、前端重点代码讲解

### 1. 登录与权限（useAuth）

```ts
// src/store/useAuth.ts
login: async (username, password) => {
  const name = username.trim();
  const pass = password.trim();

  // 管理员写死在代码里
  if (name === 'admin' && pass === '111') {
    const session = { role: 'admin', username: 'admin', teacherName: '管理员', classNo: 0 };
    persist(session);
    set({ session, isAuthenticated: true });
    return true;
  }

  // 班主任：账号是班级号，从 class_teachers 校验
  if (!/^\d+$/.test(name)) return false;
  const classNo = Number(name);
  const { data, error } = await supabase
    .from('class_teachers')
    .select('class_no, teacher_name, password')
    .eq('class_no', classNo)
    .maybeSingle();
  if (error || !data) return false;
  if (data.password !== pass) return false;

  const session = {
    role: 'teacher',
    username: name,
    teacherName: data.teacher_name || `${classNo}班班主任`,
    classNo,
  };
  persist(session);
  set({ session, isAuthenticated: true });
  return true;
},
```

讲解：

- `maybeSingle()` 最多返回一行，适合按主键查询账号。
- 会话保存到 `localStorage`，刷新后 `readSession()` 恢复登录。
- 管理员写死 `admin/111`，班主任账号存在数据库，方便在设置页统一管理。

### 3. 成绩索引与计算（scoreUtils）

#### 为什么要有索引

如果每名学生每个科目都用 `scores.find(...)`，在 28189 条记录下是 4027 × 6 次全表扫描，页面会非常卡。先按学生分组：

```ts
export function buildScoreIndex(scores: Score[]): Map<string, Score[]> {
  const map = new Map<string, Score[]>();
  for (const s of scores) {
    const arr = map.get(s.studentId);
    if (arr) arr.push(s);
    else map.set(s.studentId, [s]);
  }
  return map;
}
```

#### 取分规则

```ts
// 选考科目优先赋分，语数英只有原始分，总分只存在 raw_score
export function scoreValue(s: Score | undefined): number | null {
  if (!s) return null;
  if (s.assignedScore !== null && s.assignedScore !== undefined) {
    return s.assignedScore;
  }
  return s.rawScore;
}
```

#### 总分计算

```ts
export function totalForIndexed(index, studentId, examId): number {
  const rows = index.get(studentId) ?? [];
  const totalRow = rows.find((s) => s.examId === examId && s.subject === '总分');
  const total = totalRow ? scoreValue(totalRow) : null;
  if (total !== null) return total;
  // 没有总分行时按“语数英原始分 + 选科赋分”兜底计算
  let sum = 0;
  for (const s of rows) {
    if (s.examId !== examId || s.subject === '总分') continue;
    sum += scoreValue(s) ?? 0;
  }
  return sum;
}
```

#### 班内排名（标准竞赛排名）

```ts
export function assignStandardRanks(entries) {
  const sorted = [...entries]
    .filter((e) => e.value !== null)
    .sort((a, b) => (b.value as number) - (a.value as number));
  const map = new Map();
  let prevValue = null;
  let prevRank = 0;
  sorted.forEach((entry, idx) => {
    const rank = idx > 0 && entry.value === prevValue ? prevRank : idx + 1;
    map.set(entry.id, rank);
    prevValue = entry.value;
    prevRank = rank;
  });
  return map;
}
```

特点：同分同名次，例如 1、2、2、4（没有第 3 名）。

#### 修改成绩后重算

```ts
// 先重建总分行（语数英原始分 + 选科赋分）
next = recomputeTotalRows(state.students, next, examId);
// 再按班级重算各科与总分排名

```

`recomputeClassRanks` 内部规则：总分/选考科目按赋分排名，语数英按原始分排名。

## 五、Windows 环境踩坑记录

1. PowerShell 执行策略会拦截 `npm.ps1`、`wrangler.ps1`，统一使用 `npm.cmd`、`wrangler.cmd`。
2. PowerShell 向 Node 传中文会变成 `??`（例如 `期末考试.xls` 变 `????.xls`），解决方案：
   - 中文路径通过环境变量传给 Node；
   - 含中文的脚本写成 UTF-8 文件，不要用 here-string 内联。
3. PowerShell `ConvertTo-Json` 会把字符串包成 `{value:...}`，构造 API 请求体时用 Node 生成 JSON 文件，再交给 `curl.exe --data-binary @file`。
4. 递归删除受安全策略限制，临时生成目录（`.cf-deploy/`、`.import-data/`）保留并加入 `.gitignore`。
5. Cloudflare OAuth token 约 1 小时过期，用 refresh token 刷新后写回 `default.toml`。
